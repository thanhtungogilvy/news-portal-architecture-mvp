## Why

The news portal currently has no semantic understanding of its content. Phase 8 requires article embeddings stored in pgvector as the shared foundation for semantic search, recommendations, and RAG chatbot. Without this foundation, all three AI features are blocked.

## What Changes

- Add `pgvector` extension to Supabase
- Add `article_embeddings` table with a `vector(N)` column — dimension probed from LM Studio before migration is written
- Add `embedding_jobs` queue table following the existing `view_count_jobs` pattern
- Add LM Studio AI provider (`lmstudio.provider.ts`) — OpenAI-compatible client for embeddings and chat
- Add `embedding.service.ts` — builds embedding text from article fields, calls LM Studio, upserts vectors
- Add `article-embedding.repository.ts` — upsert and query embeddings
- Add `lib/background/embedding/` worker — processes `embedding_jobs` in batches of 5–10 with retry and failure tracking
- Add `workers/embedding.ts` entry point following existing worker pattern
- Add `POST /api/admin/embeddings/backfill` — enqueues embedding jobs for all published articles, returns HTTP 202
- Enqueue embedding job after article create/update (fire-and-forget, no sync LM Studio call in article save path)
- Add pgvector SQL RPC function for cosine similarity search

## Capabilities

### New Capabilities
- `article-embeddings`: Store and manage per-article vector embeddings generated by LM Studio embedding model
- `embedding-job-queue`: Async job queue for embedding generation with retry, batching, and failure tracking
- `lmstudio-provider`: LM Studio OpenAI-compatible API client used by all AI features

### Modified Capabilities
- `admin-news-api`: Article create/update now enqueues an embedding job after save (no breaking API change, fire-and-forget side effect)

- `server/services/ai/lmstudio.provider.ts`

- `server/api/admin/embeddings/backfill.post.ts`
- `lib/background/embedding/index.ts`
- `workers/embedding.ts`

**Modified files:**
- `server/services/news.service.ts` — enqueue embedding job after create/update
- `workers/all.ts` — register embedding worker
- `.env.example` — add `LMSTUDIO_BASE_URL`, `LMSTUDIO_EMBEDDING_MODEL`, `LMSTUDIO_CHAT_MODEL`, `AI_DEBUG`

**Dependencies:** None new — LM Studio is a local runtime, no npm package needed (plain `fetch` to OpenAI-compatible HTTP API)

**Constraints:**
- Embedding dimension must be probed from LM Studio before migration is written and must not change after articles are embedded
- LM Studio must be running for embedding generation; jobs retry with backoff on failure
- Article is live on site immediately after save; embedding is eventual (acceptable for POC)
