## ADDED Requirements

### Requirement: Chat API accepts a user message and returns structured response
`POST /api/chat` SHALL accept `{ message: string }` (required, non-empty), run the RAG pipeline, and return `{ answer: string, articles: ArticleCard[], followUpQuestions: [string, string, string] }`.

#### Scenario: Valid message, LM Studio available
- **WHEN** client posts `{ message: "AI có ứng dụng gì trong giáo dục?" }`
- **THEN** server SHALL return HTTP 200 with a non-empty `answer`, up to 5 `articles`, and exactly 3 `followUpQuestions`

#### Scenario: Empty message
- **WHEN** client posts `{ message: "" }` or omits message
- **THEN** server SHALL return HTTP 400 with a validation error

#### Scenario: LM Studio unavailable
- **WHEN** LM Studio is not reachable
- **THEN** server SHALL return HTTP 503 with `{ error: "AI_UNAVAILABLE", message: "..." }`

---

### Requirement: Chatbot answers only from retrieved article context
The RAG system SHALL ground the chatbot's answer exclusively in the top-5 articles retrieved by pgvector similarity. The LM Studio system prompt SHALL instruct the model to use only provided context and state insufficient information if context is lacking.

#### Scenario: Context is sufficient
- **WHEN** retrieved articles contain relevant information
- **THEN** answer SHALL reference information present in the retrieved articles

#### Scenario: Context is insufficient
- **WHEN** no relevant articles are found or context does not contain an answer
- **THEN** answer SHALL state that the available articles do not contain sufficient information (not hallucinate)

---

### Requirement: Chatbot responds in same language as the user's question
The system prompt SHALL instruct the model to detect the user's language and respond in that language.

#### Scenario: Vietnamese question
- **WHEN** user asks in Vietnamese
- **THEN** `answer` and `followUpQuestions` SHALL be in Vietnamese

#### Scenario: English question
- **WHEN** user asks in English
- **THEN** `answer` and `followUpQuestions` SHALL be in English

---

### Requirement: Response always contains exactly 3 follow-up questions
Every successful chat response SHALL include exactly 3 follow-up questions in `followUpQuestions`. If the model fails to produce parseable questions, the server SHALL substitute 3 generic fallback questions.

#### Scenario: Model produces valid follow-up questions
- **WHEN** model output contains parseable `{"followUpQuestions": [...]}` with 3 items
- **THEN** those questions SHALL be returned in the response

#### Scenario: Model output unparseable
- **WHEN** model output does not contain parseable follow-up questions
- **THEN** server SHALL return 3 generic fallback questions (not a 500 error)

---

### Requirement: Article cards in response come from retrieved context
The `articles` array in the response SHALL contain a subset of the top-5 retrieved articles, not generated by the model. Each article card SHALL have `title`, `slug`, `thumbnailUrl`, `summary`.

#### Scenario: Articles returned
- **WHEN** successful chat response
- **THEN** each item in `articles` SHALL have correct `slug` that resolves to a real article in the portal
